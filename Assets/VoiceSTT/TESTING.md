# VoiceSTT 테스트 안내 (엔진 A: Windows 받아쓰기)

> 7~8단계에서 사용. 마이크가 준비되면 이 순서대로 진행하고, 마지막의 "보고 양식"을 채워 Claude에게 보낸다.
> 작성: 2026-10-29

## 0. 지금까지의 상태

| 항목 | 상태 |
|---|---|
| 게임 루프 멈춤 (Unity 창이 뒤에 있으면 Update가 안 돎) | **수정 완료** (`SttBootstrap.keepRunningInBackground`) |
| 플레이 중 키보드 입력이 Input System에 들어오지 않음 | **미해결**. 플레이 시작 후 키보드 이벤트 0건, 마우스는 정상. 아래 2단계로 원인을 좁힌다 |
| 화면 버튼으로 녹음 | 아직 확인 안 됨 |
| 엔진 A 한국어 인식 | **이 PC에서는 불가로 판단**. Windows 받아쓰기 지원 언어가 en-US뿐 (SETUP.md 6-1) |
| 엔진 B (Whisper) | 구현 완료. 기본 엔진은 **Whisper tiny**. TTS 합성 음성으로는 tiny 4/6, base 6/6 통과. 실제 목소리 테스트가 필요 |

> 엔진 B는 Windows 음성 설정과 관계없다. 따라서 아래 1번의 "Windows 음성 설정"은 엔진 A를 다시 시험할 때만 필요하다.
> 엔진 B 테스트: 상단 **엔진 드롭다운**에서 "Whisper tiny"와 "Whisper base"를 바꿔 가며 같은 주문을 시도한다. 엔진을 바꾸면 모델을 불러오는 동안(1~3초) "불러오는 중"이 표시된다. 마이크 드롭다운과 음량 미터도 동작한다. 중간 결과는 없다.
> 너무 작게 말하면 "음성이 감지되지 않음"으로 실패 처리된다 (`SttSettings.minSpeechLevel`, 기본 0.25).
> 속도 비교를 하려면 `SttSettings.whisperUseGpu`를 켜고 끄며 시도한다 (기본 끔 = CPU).

## 1. 준비 (테스트 전 한 번)

1. **마이크 연결**: 설정 → 시스템 → 소리 → 입력에서 쓸 마이크를 **기본 장치**로 지정하고, 말할 때 입력 막대가 움직이는지 확인한다. 엔진 A는 Windows 기본 마이크만 쓴다.
2. **Windows 음성 설정** (한국어 인식에 필요):
   - 설정 → 시간 및 언어 → 언어 및 지역 → 한국어 → 언어 옵션 → **음성 인식** 설치
   - 설정 → 시간 및 언어 → 음성 → **음성 언어: 한국어**
   - 설정 → 개인 정보 및 보안 → 음성 → **온라인 음성 인식 켜기**
   - 설정 → 개인 정보 및 보안 → 마이크 → 데스크톱 앱 접근 허용
   - 설정을 바꾸지 않고 먼저 한 번 해 보는 것도 의미가 있다. 이때 나오는 오류가 비교 자료가 된다. 바꿨는지 여부는 보고 양식에 적는다.
3. **입력기를 영문으로**: 한/영 키로 영문 상태로 둔다. 한글 입력기가 스페이스를 가져가는 경우를 빼기 위해서다.

## 2. 기본 동작 확인 (말하기 전에)

1. Unity에서 `Assets/VoiceSTT/Scenes/STTTest.unity`를 열고 **Play**를 누른다.
2. **Game 창 안쪽을 한 번 클릭**한다.
3. 아래를 순서대로 해 보고 결과를 적는다.

| # | 동작 | 확인할 것 |
|---|---|---|
| A | 스페이스 바를 누르고 1초 뒤에 뗀다 | 왼쪽 위 상태가 **녹음 중(빨강) → 변환 중(노랑) → 완료/실패**로 바뀌는가 |
| B | 화면 아래 **"누르고 말하기" 버튼**을 마우스로 누르고 1초 뒤에 뗀다 | A와 같은지 |
| C | 녹음 중에 소리를 낸다 | **음량 막대**가 움직이는가 |

- A가 안 되고 B는 되면: 키보드 문제다. 버튼으로 테스트를 계속하고, 보고할 때 알려 준다.
- A, B 모두 안 되면: 상태가 바뀌지 않는다는 점과 콘솔 화면 캡처를 보내 준다. 이 경우 테스트는 여기서 멈춘다.

## 3. 본 테스트

1. 왼쪽 **목표 주문** 드롭다운에서 주문을 고른다.
2. 스페이스(또는 버튼)를 **누른 채 주문을 말하고**, 말이 끝나면 뗀다.
   - 평소 게임에서 말하듯 자연스럽게 말한다.
   - 상태가 "완료/실패"로 바뀐 뒤 다음 시도를 한다.
3. 주문 6개(빛나라, 찾아라, 느려져라, 불꽃아, 자라라, 숨어라)를 **각각 3번 이상** 시도한다.
4. 여유가 있으면 추가로 해 본다. 상황은 메모해 둔다.
   - 빠르게 말하기 / 작게 말하기 / 주변 소음이 있을 때
   - "어… 불꽃아"처럼 군말 섞기
   - 자유 입력으로 다른 단어 (예: "얼어라")
5. 끝나면 **Play를 멈춘다.** 이때 기록 파일이 마무리된다.

## 4. 결과가 저장되는 곳

`C:\Users\reo36\AppData\LocalLow\DefaultCompany\STT_Prototype\STTLogs\`

- `stt_YYYYMMDD_HHMMSS.csv`: 엑셀로 열 수 있음 (한글 정상 표시)
- `stt_YYYYMMDD_HHMMSS.jsonl`: Claude가 분석할 때 쓰는 파일
- `wav_YYYYMMDD_HHMMSS/attempt_001.wav …`: 각 시도의 녹음 (Unity 마이크 녹음이 켜져 있을 때)

화면의 "로그 폴더 열기" 버튼으로도 열 수 있다. **같은 PC에서 테스트했다면 파일을 보낼 필요가 없다.** Claude가 이 폴더를 직접 읽는다.

## 5. 보고 양식 (복사해서 채운 뒤 Claude에게 보내기)

```
[VoiceSTT 테스트 결과]
날짜:
PC: (이 PC / 다른 PC)
마이크: (제품명 또는 종류, 노트북 내장 등)
Windows 음성 언어: (한국어 / 영어 / 모름)
온라인 음성 인식: (켬 / 끔 / 모름)
입력기: (영문 / 한글)

[기본 동작]
A 스페이스: (됨 / 안 됨)
B 화면 버튼: (됨 / 안 됨)
C 음량 막대: (움직임 / 안 움직임 / 표시 안 됨)

[본 테스트]
시도한 주문과 횟수: (예: 6개 × 3회)
추가로 해 본 것: (빠르게, 소음 등)
테스트 환경: (조용한 방 / 소음 있음 등)

[느낀 점]
반응 속도: (빠름 / 보통 / 답답함)
자주 틀린 주문:
이상했던 점:

[첨부] (필요할 때만)
- 다른 PC에서 테스트했다면 STTLogs 폴더의 .jsonl, .csv 파일
- 오류가 났다면 Unity 화면 또는 콘솔 캡처
```

양식을 다 채우기 어렵다면 **"테스트 완료"**라고만 보내도 된다. Claude가 로그 파일을 읽고 필요한 것만 다시 묻는다.

## 6. 보고를 받으면 Claude가 하는 일 (8단계)

1. 로그를 읽어 주문별 평균 변환 시간, 평균 유사도, 성공률을 정리한다.
2. 자주 틀린 단어와 패턴을 정리한다 (예: 받침 탈락, 띄어쓰기, 영어로 인식됨).
3. 실패 원인을 분류한다 (Windows 설정, 네트워크, 무음, 마이크 충돌 등).
4. 엔진 A를 평가하고, 엔진 B(Whisper)로 넘어갈지 묻는다.
